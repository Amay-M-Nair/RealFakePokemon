# Deploying

Target is **Render's free tier** — the only real free tier left among Render /
Railway / Fly.io (Railway ended theirs in 2023; Fly.io is trial-only for new
accounts). 512 MB RAM, free Postgres, custom domains, spins down after 15 min
idle.

Measured resident memory is **396 MB peak**, leaving ~116 MB of headroom. See
[results.md](results.md#measured-resident-memory).

---

## 1. Publish the model

The trained generator is **not committed** — it is derived from copyrighted
artwork and has no business in git history. Host it and fetch it at build time.

```bash
python -m src.export_onnx checkpoints/fastgan/final.pt \
    --out server/models/generator.onnx --fp16
```

Upload `generator.onnx` (55.6 MB) and `z_mean.npy` to a Hugging Face model repo,
then note their resolved URLs:

```
https://huggingface.co/<user>/<repo>/resolve/main/generator.onnx
https://huggingface.co/<user>/<repo>/resolve/main/z_mean.npy
```

Put the same non-affiliation disclaimer on that repo as on the site.

---

## 2. Deploy

`render.yaml` is a blueprint — point Render at the repo and it provisions the
web service and Postgres together. Set these in the dashboard:

| Variable | Value |
|---|---|
| `SECRET_KEY` | generated by Render |
| `ALLOWED_HOSTS` | your domain (Render's own hostname is added automatically) |
| `GENERATOR_THREADS` | `1` |
| `GENERATOR_CHUNK_SIZE` | `2` |
| `DATABASE_URL` | wired from the Postgres instance |

The model URLs are Docker **build args**, not env vars:

```
MODEL_URL=https://huggingface.co/<user>/<repo>/resolve/main/generator.onnx
Z_MEAN_URL=https://huggingface.co/<user>/<repo>/resolve/main/z_mean.npy
```

Health check path is `/healthz`, which returns 503 rather than 200 if the model
failed to load — so a deploy that silently shipped without weights fails
loudly instead of serving errors.

---

## 3. Verify before trusting it

```bash
# Build with a real memory ceiling -- do this before deploying, not after.
docker build --build-arg MODEL_URL=... --build-arg Z_MEAN_URL=... -t pokedex .
docker run --rm -m 512m -e SECRET_KEY=test -e ALLOWED_HOSTS=localhost \
    -e SECURE_SSL_REDIRECT=0 -p 8000:8000 pokedex
```

Then check the three things that actually matter:

```bash
curl -s localhost:8000/healthz                       # {"status":"ok","model":true}
curl -s localhost:8000/g/42-80.png -o a.png
curl -s localhost:8000/g/42-80.png -o b.png
cmp a.png b.png && echo "deterministic"              # permalinks depend on this
curl -sI localhost:8000/g/42-80.png | grep -i cache-control   # immutable, max-age=31536000
```

If `cmp` ever disagrees, stop — the immutable cache headers are lying and every
CDN in front of the app will serve stale, wrong images.

## Cold starts

Free services spin down after 15 minutes idle, so the next request waits 30–60 s
while the container restarts and loads the 55.6 MB graph. Two options:

- **Accept it** and say so on the page. Honest, free, fine for a portfolio piece.
- **Keep it warm** with an UptimeRobot ping to `/healthz` every 10 minutes.
  Works, though it does consume free-tier hours continuously.

Cold start is *only* the container restart. Once warm, the first image is 0.29 s
and subsequent ones 0.31 s.

---

## Why this fits at all

Serving PyTorch would not work: torch on CPU is ~800 MB installed and ~300 MB
resident before any model is loaded. `requirements/serve.txt` deliberately never
installs it — onnxruntime is ~50 MB, and the fp16 graph is 55.6 MB.

The second half is that **`POST /api/generate` runs no inference**. It picks
seeds and returns markup pointing at `GET /g/<seed>-<psi>.png`, which is
deterministic and immutable. Every image is a shareable permalink, and repeat
traffic is served entirely by the CDN at zero CPU cost.
